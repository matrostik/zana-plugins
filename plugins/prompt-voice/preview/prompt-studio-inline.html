RFC-104: Distributed Redis Rate Limiting Middleware #

Status: Draft Review Author: Prompt Architect dns Target: /api/v1/auth/ratelimit 382 words • ~2 min read

01. Background & Operational Context

The existing tier-1 edge proxy cluster relies on sticky in-process leaky buckets. During high-concurrency burst workloads (e.g., promotional drops and synchronous auth verification spikes), inter-node token synchronization desyncs by upwards of 420ms, yielding erratic HTTP 429 cascades and degraded downstream service availability.

This document formalizes the production prompt spec and technical design contract for implementing atomic Redis-backed sliding window evaluation, standardizing HTTP header schemas, and deploying immediate circuit fallback policies.
